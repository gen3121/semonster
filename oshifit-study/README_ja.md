# OshiFit 研究版（oshifit-study）

参加者向けアプリ（`public/index.html`）・開発者ページ（`public/admin.html`）・Firestore のルール・分析（`analysis/`）。
作業の決まりは `CLAUDE.md`、保存するデータと CSV の形は `DATA_SCHEMA_ja.md`、分析の手順は `analysis/ANALYSIS_ja.md`。

## 決めたこと
- PSS-J は文言・選択肢を変えない（検証済みの尺度のため）。「頻度の受け取り方に個人差がある（例：2回中2回を『ほとんどなし』と答える人がいる）」ことを、論文の限界に書く（2026-11-17）
- 提案を増やすほど続ける負担も増えると考え、見込みに入れる（2つめから提案1つにつき推し疲れ +3 点。仮定 v1.2）

## モード（`public/config.js`）

| `OSHIFIT_MODE` | 使いみち | 保存 | 編集者モード・回答の自動補完 |
|---|---|---|---|
| `"demo"`（/editor のとき） | 展示（学祭）・画面の確認 | しない（通信もしない） | あり |
| `"study"`（/ のとき） | 本実験 | Firestore（東京）に保存 | なし（同意前・回答前の画面には入れない） |

## 公開の前にすること（今井が確認してから）

1. `public/config.js` の `OSHIFIT_FIREBASE` に、Firebase コンソール →「プロジェクトの設定」→ ウェブアプリの値（apiKey・messagingSenderId・appId）を貼り、`OSHIFIT_MODE = "study"` にする
2. Firebase コンソール（プロジェクト `oshifit-34941`）→ Authentication →「ログイン方法」で、参加者用に「メール / パスワード」、開発者用に「Google」と「メールリンク（パスワードなしでログイン）」を有効にする。「設定 → 承認済みドメイン」に公開する URL（例 `oshifit-34941.web.app`）があるか確認
   - Firestore を作るときの場所は「asia-northeast1（東京）」を選ぶ（あとから変えられない）
3. Firestore に `admins/{大学のメールアドレス}` の文書を作る（今井・大井先生の2件。中身は空でよい）。開発者ページはこの2人だけが全件を閲覧できる
4. プレ実験の参加者は、Firestore の `pilots/{参加ID}` に文書を作る（アプリの外で管理する案B）。CSV の `pilot` 列が 1 になる
5. 公開：`npx firebase-tools deploy --only "hosting,firestore:rules"`（PowerShell では引用符が必要）

## 試験（この環境で実行済み）

```bash
cd tests && npm install
npx firebase emulators:exec --project demo-oshifit --only auth,firestore,hosting --config ../firebase.json "node --test rules.test.js && node e2e_study.js"
node --test questionnaire_sync.test.js
node demo_check.js            # 展示用が通信せずに動くか
node personalization_check.js # 性格だけが違う2人に違う提案が出るか・組み合わせ・群A
```
- `rules.test.js`：ルール8件（自分の記録だけ・群は変えられない・回答は確定後に変えられない・振り返りは一度だけ・開発者は閲覧のみ など）
- `admin_check.js`：開発者ページの「設定と管理」を、エミュレーターの Google ログインで実際に操作して確認（条件を作る・変える・理由がないと保存しない・範囲外を断る・固定・提案を出さない・運用の基準・コンソールでの直接変更への警告・固定を外す）
- `e2e_study.js`：エミュレーター上で、新規登録 → 途中でログアウトして再開 → 短縮版の質問 → アバター → 群B → 毎日のアンケート → 4日後の振り返り（前回からのまとめ） → CSV と ZIP の書き出し → マイページに「参加をやめる」がないこと、まで実際のブラウザで確認
- Playwright は `PLAYWRIGHT_MODULE` で場所を指定する

## 分析（研究者側）

手順は `analysis/ANALYSIS_ja.md`。開発者ページの CSV を `data/`（コミットしない）に置いて：
```bash
pip install -r analysis/requirements.txt
python -m analysis.run --data data --out out        # 分析レポート.md と各手順の結果
python -m analysis.make_synthetic --out syn --n 120 # 動作確認用の合成データ（結果に使わない）
python -m pytest analysis/tests -q                   # 15件
```

## 研究のデータを保存する手順（実験の途中・終わったあと）

1. 開発者ページ（https://oshifit-34941.web.app/admin.html）に大学のアカウントでログインする
2. 「分析用にまとめて書き出す（ZIP）」を押す → `oshifit_data_YYYY-MM-DD.zip` が保存される
   - 中身：`baseline.csv`（開始時）・`weekly.csv`（振り返り）・`daily.csv`（毎日）・`trial.csv`（最後の調査）・`free.csv`（自由記述）・`README_export.txt`（書き出した日時と行数）
   - 列の意味は `DATA_SCHEMA_ja.md`。CSV は UTF-8（BOM 付き）で、Excel でそのまま開ける
3. ZIP はリポジトリの外（大学の OneDrive など、アクセスを限ったフォルダ）に置く。リポジトリにはコミットしない
4. 分析：`python -m analysis.run --data <ZIP> --out <結果のフォルダ>`（ZIP のまま渡せる）
5. 途中経過の確認にも使えるよう、週に1回ほど書き出して残しておくと、万一のときに戻せる

## Firestore の3つの層と、管理のしかた

| 層 | コレクション | 中身 | 変えてよいか |
|---|---|---|---|
| ① 参加者のデータ | `participants/{uid}`（下に `daily`・`checkins`） | 回答・得点・群・見込み・群を決めたときの条件の版（`cfgVersion`・`cfgUsed`） | だれも書き換えられない（開発者は読むだけ） |
| ② 実験の条件 | `study/protocol`（下に `history`・`events`）、`plans/{id}` | 振り返りの間隔・回数、最後の調査の日、群Aの基準、提案の重み・倍率・負担、見込みの幅、個人補正／提案の題名・やり方・効果の値 | 開発者ページからだけ。変えると版が上がり、記録が残る。実験が始まったら「固定する」 |
| ③ 運用 | `ops/alerts`、`notices/{id}`、`notes/{研究用の番号}` | 確認が必要の基準／お知らせ／研究者のメモ・分析からの除外 | いつでも |

**最初にすること（公開したあと、実験の前に一度だけ）**：開発者ページの「設定と管理」で
1. 「初期値で実験の条件を作る（版 1）」
2. 「今の提案を plans に書き込む」（固定すると新しく書き込めないので、固定より先に）
3. 実験を始める日に「固定する」

**注意**
- ②を Firebase のコンソールで直接変えると、ルールを通らないため記録が残りません。必ず開発者ページから変えてください（直接変えると、開発者ページに警告が出ます）
- ②を変えたら、その版より前に群を決めた参加者は前の条件のままです。変える前に指導教員と確認し、理由を書いてください。提案の題名・やり方は倫理委員会で承認済み
- お知らせは Firestore のコンソールの notices で追加・編集します（項目は開発者ページに説明あり）
- 初期値そのものは `public/settings.js`（条件）と `public/plans.js`（提案）にある
