## 1. 何を作っているか

OshiFit は、推し活（ファン活動）を性格と行動から分析し、本人に合った推し活の調整を提案して、幸福度を保ちながら推し疲れを減らすことを目指す、修士研究のウェブアプリ。

- 質問紙で性格（TIPI-J）と推し活の中身・負担を測り、6つの軸で状態を見せる
- 群A（すでに良好）は「今のままで順調」と伝える
- 群B・Cには、本人の写真から作った似顔アバターで2つの未来を見せ、本人に選ばせる
  - **プランA「現在のままの推し活」**
  - **プランB「最適化された推し活」**
  - 「Path A/B」という表記は使わない（2026-10-22 に統一済み。コードにも画面にも残さない）
- 選んだあと、振り返りを繰り返し、最後の調査で前後比較する

設計原則（論文 3章）：
- D1：一律に減らせとは言わない。「今のまま」を常に選べる
- D2：行動と負担を主な手がかりにし、性格は優先順位づけに使う
- D3：利点と負担を一緒に見せる（トレードオフも）
- D4：不確かさに正直に。見込みは80%区間で示し、差が小さいときは「ほぼ同じ」と書く。算出式と項目を開示する

## 2. 現在の構成（研究版）

- 形式：スマートフォンのブラウザで動く単一ページのウェブアプリ（HTML / CSS / JavaScript、ビルド工程なし）
- ホスティング：Firebase Hosting　https://oshifit-study.web.app
- データ：Cloud Firestore（プロジェクト `oshifit-study`、リージョン asia-northeast1 東京、変更不可）
- 認証：匿名（参加者）、Google とメールリンク（開発者ページ）。匿名アカウントの30日自動削除は**オフ**のまま（研究途中で記録が消えるため）
- 料金：無料の Spark プランの範囲で作る。有料の外部APIは使わない
- アバター：MediaPipe Face Landmarker（Web版）。**写真と顔の特徴点は端末の外に送らない・保存しない**
- 質問項目と採点規則は `questionnaire.json` に置き、画面に出す算出式と計算を一致させる

主なファイル（`public/` 以下）：
| ファイル | 役割 |
|---|---|
| `index.html` / `app.js` | 参加者向けアプリ本体 |
| `questionnaire.json` | 質問・選択肢・尺度・採点規則 |
| `config.js` | `OSHIFIT_MODE`（`"study"`＝研究版、`"demo"`＝展示用で保存なし）と Firebase の設定値 |
| `admin.html` | 開発者ページ（今井と大井先生の大学アカウントだけが閲覧可能） |
| `firestore.rules` | 参加者は自分の記録だけ読み書き可、管理者だけ全件閲覧 |
| `README_ja.md` | 運用手順（公開・PSS-J・プレ実験・分析） |
| `ANALYSIS_ja.md` | 分析手順 |

その他：`model/`（予測モデル M1：予備調査215名から学習した係数を JSON に固定、ハッシュ付き）、`analysis/`（Python の分析パイプライン：k-means、semopy による SEM、PC アルゴリズム、Double Machine Learning。手順0〜9）、`tools/add_pss.py`。

> 古い試作（FastAPI＋React Native/Expo）は研究版では使っていない。触らない。

## 3. 実験の仕様（倫理審査で承認済みの内容に合わせること）

**ここを勝手に変えない。** 質問の文言・選択肢・尺度・提案の題名は倫理委員会で承認済み。変えるときは必ず今井に確認し、倫理委員会への届けが必要かを判断してもらう。

- 開始時（約15分）：同意 → 質問紙 85項目（67項目＋SHS 4項目＋PSS-J 14項目）→ アバター作成 → 6軸の結果と算出式 → 群の判定
- 尺度
  - TIPI-J：**5件法**（原版の7件法から研究全体で5件法に統一）
  - 気持ちと生活・推し活をしたくなるとき：7件法
  - 推し活の中身：回数ではなく「自分の推し活全体の中での割合」を5段階
  - WHO-5：6段階
  - PSS-J：14項目（Mimura & Griffiths, 2008）。肯定的な P4・P5・P6・P7・P9・P10・P13 は分析で逆転（0〜56点）。原文の「〇をつけて下さい」だけ「選んで下さい」に変更済み
  - すべての選択肢に数字と言葉を付ける
- **振り返りの間隔（2026-11-06 変更、最新）**
  - 週1回・6週間 → **4〜5日ごとに6回・約4週間**
  - 前回から4日たつまで振り返りボタンは押せない
  - 3回目の振り返りだけ WHO-5 を追加
  - 最後の調査は開始から **28日目以降** に開く（6回を終えていなくても35日目には開く。群Aは28日目）
  - 記録の `week` は「何回目か」（1〜6）、`day` は開始からの日数。分析は日数で行う
  - 画面に「週」「6週」「今週」「この1週間」を残さない。ただし承認済みの提案題名「今週追うものを3つに絞る」はそのまま
- 開発者ページの「確認が必要」：10日以上振り返りがない人、WHO-5 が7点以下の人
- 安全面：相談先の表示、群が決まるまで下のタブ（分析・未来）を出さない、選んだ群は途中で変えられない、「参加をやめる（記録を削除）」
- プレ実験の参加者も本実験に参加可。プレ実験のデータは本実験に入れない。`trial.csv` の `pilot` 列で除外した感度分析を出す

## 4. デザインの決まり

- モチーフ：ペンライトの光。操作色はビビッドなマゼンタ
- 色の意味：**利点・良い結果＝青、負担・デメリット＝赤**。パステルは使わない
- 文字：見出し Zen Kaku Gothic New、本文 BIZ UDPゴシック（丸ゴシックは使わない）
- AIっぽい見た目の画像・人物を避ける
- 上部に進み具合（質問→アバター→分析→2つの未来）、下部に固定の「次へ」ボタン。ダークモード対応
- 展示（学祭）用の体験版は保存しない。「最初から」は確認画面と10秒間の「元に戻す」付き
