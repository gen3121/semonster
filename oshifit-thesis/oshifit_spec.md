# OshiFit 論文の指示書（oshifit_spec.md）

この論文の執筆・分析は、このファイルを「唯一の正」として進める。ここに書いていないことは推測で埋めず、「未決事項」に積んで研究者（今井）に聞く。新しい知見や決定が出たら、その都度ここに追記する（最後の「変更履歴」にも1行書く）。

- 情報源：プロジェクトのチャットで作った画面試作（artifact「OshiFit 画面試作」、2026年11月時点）、このリポジトリの `prototype/`・`analysis/`・`docs/`。
- 両者が食い違う点は、**プロジェクトのチャット側（画面試作）を新しい設計として採る**（研究者の指示：プロジェクトのチャットのほうが議論が進んでいる）。食い違いは第8節に一覧にした。

## 1. 研究の一文要約

推し活の状態を5つの要素で見える化し、性格と活動の比重に合わせた小さな提案を「今のまま（プランA）」と「提案を試す（プランB）」の2つの未来として示すシステム OshiFit を作り、4週間の使用で幸福度とストレスがどう変わるかを調べる。

## 2. 背景と、本研究の意義

- 推し活は生きがい・ストレス解消になる一方、睡眠・お金・義務感・SNSでの比較による「推し疲れ」を生むことがある。【要出典：推し活の効果と負担に関する先行研究。研究者が選定】
- 既存の支援は「やめる・減らす」方向に偏りがちで、推し活を楽しむこと自体を保ったまま負担を減らす仕組みは少ない。【要出典】
- **本研究の意義（研究者の言葉）**：単なるWebサイトの開発にとどまらず、システムによる適切な推し活の提案が、ウェルビーイング（幸福度の向上・ストレスの緩和）に寄与することを示す点。
- **書き方の注意**：本研究の群分けは本人の選択による（第4節）ため、「提案が幸福度を上げた」という**因果の断定はできない**。論文では「提案を選んで実行した人で、幸福度の向上が見られた（関連）」のように書き、因果の主張は限界として明記する。「実証する」という語は、結果が出てから研究者と相談して使う。
- 独自性の候補（研究者が確定する）：
  1. 推し活を「減らす」のではなく、5つの要素と性格・活動の比重から「組み替える」提案
  2. 提案ごとに研究の確かさ（3段階）と根拠を示す透明性
  3. 似顔アバターで「2つの未来」を並べる提示（プロテウス効果・未来の自己の考え方。【要出典】）
  4. 「今の推し活は順調です」と、提案しない判断もする（群A）

## 3. システム概要（画面試作の設計）

1. **最初の調査（約86問・約15分）**：選ぶと自動で次の質問へ。
   - 基本情報（年齢・性別・職業・推しのジャンル・期間・推しの数・月の金額）
   - 性格（TIPI-J、5件法）
   - 推し活の中身（12活動それぞれが推し活全体に占める割合、5段階）
   - 推し活を通じた気持ちと生活（26項目、7件法。注意確認の項目を1つ含む：Q42 は「2」を選ぶ）
   - 推し活をしたくなるとき（7項目、7件法）
   - WHO-5（最近2週間の気分）、主観的幸福感 SHS（島井ほか, 2004）、ストレス PSS-J（Mimura & Griffiths, 2008）
   - 自由記述（任意）
2. **アバター**：パーツで作る。写真から作る場合は端末の中で顔の比率と色を読み取るだけで、保存も送信もしない。
3. **分析画面**：5つの要素（推し活の充実・睡眠と生活・お金・義務感と人間関係・SNSと比較）を0〜100点（高いほど良い向き）で示し、60点以上を青（良好）、60点未満を赤（見直したい）。結果として、幸福度（WHO-5）とストレス度（PSS-J）、推し疲れ（8項目）を示す。算出の根拠を開ける。
4. **群の決め方**：
   - **群A（今のままで順調）**：6軸のうち5軸以上が60点以上、かつ WHO-5 素点13以上。提案はしない。28日目に最後の調査だけ。
   - それ以外の人には「2つの未来」画面で、提案（最大3つ）とプランA／Bを並べる。
   - **群B**：提案を1つ以上選んで始める（プランB）。
   - **群C**：提案を選ばず、今のままで続ける（プランA）。
5. **提案の選び方（v1.1）**：提案の候補は15種類（睡眠・お金・義務感・比較・充実・幸福度の各軸）。各候補の点数 ＝（その軸の「ふつうの目安」− 本人の得点）＋ 性格との合い方 × 12 ＋ その活動の比重 × 18。点数の高い順に、軸が重ならないよう3つまで。推しが2人以上で義務感が60点未満の人だけに「追う予定を3つまでに絞る」を出す。予算の提案は本人の金額の区分の約8割を上限の目安にする。
6. **提案の根拠**：提案ごとに研究の確かさ（★3：介入研究で確認／★2：実験や近い介入研究／★1：調査研究や理論）と、説明・参考文献を表示する。
7. **2つの未来**：プランA（今のまま）とプランB（選んだ提案）の4週間後の見込みを、似顔アバターと5要素のレーダー、幸福度・ストレスの棒で並べる。見込みは「想定の効果を足し合わせた仮の値」で、選んだ数が多いほど幅を広くする。
8. **振り返り**：群B・Cは、4〜5日ごと（前回から4日以上あける）に6回、各約2分。提案を行ったか、前回と比べたストレス・幸福感、気づき（メタ認知）を聞く。3回目だけ WHO-5 も聞く。
9. **最後の調査**：28日目以降に開く（振り返りが6回そろっていなくても、35日目には開く）。開始時と同じ尺度で、前後の変化を見る。
10. **研究者ページ**：大学のGoogleアカウントでログイン（登録した研究者のみ）。進み具合、要確認の参加者（振り返りが10日以上ない等）、CSVの書き出し（`baseline.csv`、`weekly.csv`）。
11. **安全**：つらい状態が続くときは、振り返りを休んでよいこと、学生相談室・厚生労働省「まもろうよ こころ」を案内する。

## 4. 研究デザイン

- 種類：**介入を伴う前後比較の観察研究**（群は本人の選択による。無作為割り付けではない）。
- 比較：
  - 主：群B（提案を選んだ）の開始時 → 28日目の変化。
  - 比較：群C（今のまま）の変化。群B と C は、開始時の得点・性格などで調整して比べる。
  - 参考：群A（順調）の自然な変化。
- 用量反応：群B で、振り返りで「提案を行った」と答えた回数（実行の程度）と変化の関係。
- 限界（論文に必ず書く）：自己選択による偏り、自己報告、短期間（4週間）、対象の偏り（予備調査はほぼ大学生）。

## 5. 検証項目と分析計画

### 検証項目1：提案の精度（見込みはどれくらい当たったか）

- 「2つの未来」で示した、プランB の28日目の見込み（点推定と幅）と、28日目の実測を比べる。
- 指標：平均絶対誤差（MAE）、見込みの幅に実測が入った割合（包含率）。群C ではプランA の見込みで同じことをする。
- 補助：提案の「選ばれ率」「実行率」、見送り・実行できなかった理由。

### 検証項目2：心理的効果（幸福度・ストレス）

- 主な指標：WHO-5（0〜100換算）、PSS-J（0〜56）。副：SHS（1〜7）、推し疲れ（0〜100）、5つの要素。
- 分析：
  - 群内の前後比較：対応のある t 検定（または Wilcoxon）と効果量。
  - 群間の比較（B 対 C）：28日目の値を目的変数、開始時の値・性格を共変量にした共分散分析（ANCOVA）。偏りの補正として傾向スコアによる重みづけを感度分析に置く。
  - 振り返りごとの変化：混合効果モデル（参加者を変量効果）。
- WHO-5 は10点以上（100点換算）の変化を臨床的に意味のある変化の目安とする。【要出典：Topp et al., 2015 の記述を確認】
- 有意水準・多重比較の扱い・欠測の扱い：【未決】

### 予備調査（215名）との関係

- 予備調査は、5件法・逆向き（1＝よく当てはまる）の別の質問紙で、項目が新しい質問紙と一致しない（第8節）。予備調査は「背景と提案の考え方の根拠」として使い、本実験の数値と直接はつなげない。

## 7. 執筆・分析のルール（自走するときの約束）

1. **数値・結果を作らない**：結果の章には、`data/` の実データから `src/` のスクリプトで出した値だけを書く。データがない段階では「（結果はデータ収集後に記入）」と書き、架空の数値は書かない。
2. **文献を作らない**：引用は、研究者が選定した文献か、書誌を確認できた文献だけ。確認できていないものは `\todo{要出典}` か、`references.bib` の `note = {書誌未確認}` を付ける。画面試作の参考文献（第9節）は、論文に使う前に原典で確認する。
3. **因果の書き方**：第2節の注意に従う。
4. **字体**：PDF・図はすべて BIZ UDPゴシック（リポジトリの `CLAUDE.md`）。数式は最小限にし、記号は言葉で書く。
5. **個人情報**：`data/` の実データはリポジトリにコミットしない（`.gitignore` 済み）。自由記述を引用するときは、個人が特定できないように一部を言い換え、研究者に確認する。
6. **疑問の扱い**：調べて決められる → 決めて「変更履歴」に記録。仮置きで進められる → 仮置きし「未決事項」に追加。研究者しか分からない・取り返しがつかない（提出・公開・削除） → 止めて聞く。
7. **ビルド**：`cd paper && latexmk` で `main.pdf` を作る（LuaLaTeX）。エラーが出たら直してから終える。
