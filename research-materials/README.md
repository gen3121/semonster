## 提案したシステム：OshiFit v2

計画書の OshiFit（TIPI-J＋記録 → 予測 → Path A／B をアバターで提示）に、次の4つの仕組みを加えた設計です。

1. **ベイズ個人ツイン**：予備調査215名の係数を事前分布にし、毎日の記録で個人差を毎晩更新します。計画書の「2週間で個人補正（混合モデル）」を毎日少しずつ進む形にしたもので、予測区間が自然に得られます。
2. **ゆらぎアバター（みらいミラー）**：予測の幅を、20通りの未来から描いた「ありうる自分たち」の重なりで見せます。記録が増えると重なりが収束して未来の自分がくっきりします（「未来の解像度」）。予測精度が低い（推し疲れ R²≈.11）ことを隠さずに見せ、それ自体を記録を続ける動機にするのが最大の独自点です。
3. **リバランス提案エンジン**：「減らす」ではなく「組み替える」提案です。7活動×±1段階の98案から、本人の「増やしたい」を減らさないパレート最適な3案（楽しさキープ／バランス／回復重視）を出します。
4. **疲れの中身キュー**：睡眠・出費・義務感・比較を、アバターの控えめな手がかり（くま、軽い財布、重いリュック、スマホの光）で表し、提案もそれに合わせます。

群Bと群Cの差は「予測値とゆらぎアバターの有無」だけにそろえてあり（群Bの提案カードには予測値を出さない）、計画書の RQ2 の比較が崩れないようにしています。

## 使う前に確認・差し替えが必要なところ

- **想定値**：進捗②〜④と発表①②の人数・割合・統計値・自由記述は、すべて**仮の値**です。該当スライドのフッターにピンクの「※ 想定値」ラベルを付けてあります。実データが出たら `src/projected.py` の値を書き換えて作り直すか、スライドを直接編集し、ラベルを消してください。
- **輪講の数値**：Hershfield et al. (2011) の各研究の人数・条件・数値（$172 vs $80 など）と、Kay et al. (2016) の実験の詳細（条件数・参加者数）は二次資料しか確認できませんでした。スライドとノートに「原著で確認」と書いてあるので、発表前に原著の値に差し替えてください。
- **公聴会の表紙と研究業績**：所属の表記、指導教員名、AIxMHC と情報処理学会関西支部大会の題目（「（仮題）」「（題目）」の部分）、CHIIR の採否は仮です。
- **日付**：進捗・輪講の日付は、これまでの資料と同じく金曜日と仮定しています。
