## 2. 動作確認の結果（ローカル試用版）

- `study-system-v1/app` を `npm run web -- --port 3020` で起動し、`http://127.0.0.1:3020/` で確認した。
- TIPI-J → 推し活 → WHO-5 → 気になること → アバター → 結果、の流れが最後まで動き、コンソールエラーはなかった。

## 3. 導入した開発支援ツール（Qiita記事より）

- 参照記事: https://qiita.com/shatolin/items/ca1810e419fee5fd963b
- 計画書の開発に関係する2つだけを `study-system-v1/.mcp.json` に設定した。
  - Context7（Expo・Supabase等の最新ドキュメント参照）
  - Playwright MCP（画面操作・スクリーンショットによる検証）
- 記事のほかの項目（Claude-Mem、Superpowers 等）は導入していない。
- `claude` コマンドが PATH に無かったため、`claude mcp add` ではなく設定ファイルを直接作成した。有効になるのはプロジェクトを開き直して承認した後。

## 4. アバター

- 方針: 「アバター作成はもっと人間らしくさせたい」（ユーザー指示）。
- `study-system-v1/app/components/Avatar.tsx` を描き直した（陰影つきの肌、耳・鼻・唇、白目・虹彩つきの目、毛束感のある髪、首と肩）。入出力（`parts` / `state` / `size`）は変更していない。
- 計画書の「大げさな疲弊表現は行わない」に合わせ、疲れ状態の汗の表現は外した。疲れは顔色・眉・頭の傾きで控えめに表す。
- 確認済み: 短め・ロングの髪型（通常状態）。未確認: 元気・疲れ状態の見た目。

## 5. 計画書と実装のずれ（洗い出し結果）

### 補ったもの

- 評価方法1「6週時点の予測値と実測値の差」が未実装だったため追加した。
  - `core/src/export.ts`: 書き出しに予測（点推定・80%区間・表示有無）を追加。群Bでも計算して保存し、画面には出さない（displayed=0）。
  - `analysis/prediction_accuracy.py`: MAE・RMSE・R²・区間への実測の包含率を出力。
  - シミュレーションデータで動作確認済み（乱数データのためR²≒0は想定どおり）。

### 実装が計画書と異なる点（未対応・要判断）

- 個人補正: 計画書は混合モデル、実装は簡易の縮小推定（n/(n+2)）。
- H1（提案の実行）の主解析: 計画書はロジスティック混合モデル、実装はロジスティックGEEを主、混合モデル（変分ベイズ）を確認用にしている。どちらを主解析にするか決める必要がある。
- H1の「実行」の定義: 「できた」「一部できた」を1、「できなかった」を0とした。「できた」のみを1とする解析を感度分析として併記する。

## 追記（2026年10月9日・もう一方のセッション〔semonster リポジトリ側〕から）

上の記録とこちらの作業をつなぐための事実だけを書く。解釈や決定は含めない。

- **予備調査の回答の向き（上の第7節の確認事項）**: 実データ（215名）で確認した結果、**逆向き（1＝よく当てはまる／高頻度）** だった。報告されている割合と照合して判断し、分析では 6−x にそろえて使っている（`analysis/prepare.py`）。`study-system-v1/model/fit_m1.py` の入力の向きが、この結果と合っているかの確認が必要。TIPI-J も同じ向きと仮定しており、フォームの文言での確認が必要。
