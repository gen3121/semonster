# OshiFit 試作アプリ（ブラウザで動く版）

`index.html` をダブルクリックするだけで動きます（サーバー・インストール不要）。スマホで使うときは、フォルダを公開したURLを開いてください。
データは端末の中（localStorage）にだけ保存され、どこにも送信されません。

> **試作版です。** 予測の係数は仮の値で、研究で使う値ではありません（`js/model.js` の `PARAMS`）。
> 実験で使う前に、予備調査215名から作った予測モデル v1.0 の係数に差し替えてください。

## できること

| 画面 | 内容 |
|---|---|
| 初回設定 | 同意 → TIPI-J（10問）→ 増やしたい・減らしたい活動／使ってよい金額・使える時間 → パーツで作る似顔アバター |
| 記録（会話） | 毎日「ひとこと」を書く → ルールで項目を取り出す → 足りない項目だけ最大3問で聞き返す → 楽しさ・疲れは必ず1〜5で聞く → 確認カードで直せる。LLM は使わない。2週ごとに WHO-5 も会話で答える |
| 安全層 | 強い言葉・疲れ5が3日連続・WHO-5 素点13未満で相談先を表示。強い言葉のときは記録を保存せず、予測の表示も止める |
| 今週の提案（群B・C） | 5活動のうち最大2つを±1段階動かした候補を予測し、「増やしたい」を減らさない3案を出す。1週間後に実行できたかを聞く |
| いまの状態（群C） | ストレス（睡眠・出費・時間・疲れ・気持ち）のレーダーと0〜100の数値、幸福度（WHO-5）のレーダーと数値。数字ごとの「この数字の根拠」ボタンで、計算式・あなたの入力値・限界が開く |
| ミラー（群C） | 「今のまま」と「提案どおり」を、似顔アバター1体ずつ・見込み・80%の幅・「20人中◯人が疲れ高め」で並べる。先週の見込みとの答え合わせ |
| 設定 | 記録の書き出し（本文は含めない）、相談先、データ消去、研究者コード（群の割り付け） |

群は、記録のみの2週間のあと（15日目から）に割り付けた群の画面になります。それまでは全員、記録だけです。
開発用に `index.html?dev=1` で開くと、設定の下に「+1日」「+7日」「デモ14日分を入れる」が出ます。

## 「いまの状態」の数字の出し方

直近14日の記録から計算します（`js/state.js`）。すべて 0〜100 で、ストレスは大きいほど負担が重く、幸福度は大きいほど良い状態です。

| 数字 | 計算式 |
|---|---|
| 睡眠 | 睡眠への影響の平均（なし0・少し1・かなり2）÷ 2 × 100 |
| 出費 | 1週間あたりの支出 ÷ 使ってよい額（月の目安 × 7/30）× 100（上限100） |
| 時間 | 1日あたりの配信・動画とSNSの時間 ÷ 使える時間 × 100（上限100） |
| 疲れ | 疲れ（1〜5）の平均 → (平均 − 1) ÷ 4 × 100 |
| 気持ち | 「いちばんの疲れ」が義務感または比較だった日 ÷ 疲れを答えた日 × 100 |
| ストレス総合 | 5軸の平均（重みは等しい。試作の仮） |
| 幸福度 | WHO-5 の素点（0〜25）× 4（Topp et al., 2015） |

「ゆとりあり／ふつう／重め」の区切りは三等分の仮の目安です。一般の平均との比較ではありません。

## まだ作っていないもの・仮のもの

- 予測の係数は仮（上記）。個人差の事前の大きさ・週平均の揺れの係数なども仮。
- 写真からのアバター生成（顔の特徴点）。パーツ選択のみ。
- サーバーへの送信・群の自動割り付け・通知（毎日の通知）。記録の書き出しで代用。
- 倫理審査の承認を得た説明文書（同意画面の文面は仮）と、相談先の確認（`data/resources.json`・`js/resources.js` は両方そろえて変更）。
- 疲れの中身（睡眠・出費・義務感・比較）のアバターの手がかり。
- 実際の利用者による操作確認。
- LLM による読み取り（使わない設計。ルールの辞書は `js/extract.js`。実際の言い回しに合わせて育てる必要がある）。
