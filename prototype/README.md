# OshiFit 試作アプリ（ブラウザで動く版）

質問紙（予備調査215名で使った項目）をそのまま軸にした、会話型の試作アプリです。

- そのまま使う：`index.html` をダブルクリック（サーバー不要。AI読み取り・写真アバターは使えません）
- AI読み取りと写真アバターも使う：`bash tools/vendor_mediapipe.sh`（顔の特徴点の部品を入れる・初回のみ）→ `cd server && npm install && ANTHROPIC_API_KEY=... node proxy.js` を起動し、`http://localhost:8787/` を開く（詳細は `server/README.md`、`PHOTO_AVATAR.md`）

データは端末の中（localStorage）にだけ保存します。自由な文章そのものは保存せず、読み取った回答の数字だけを残します。

> **試作版です。** 予測は予備調査215名の「関連」にもとづく見込みで、頻度を変えたときの効果ではありません（予測の当たり具合は幸福度 R² ≈ .19、推し疲れ R² ≈ .10。`analysis/README.md`）。

## 流れ

| 時期 | 内容 |
|---|---|
| 初日 | 同意（AI読み取りを使うかは任意の選択）→ 似顔アバター（パーツ／写真）→ **会話インタビュー**：WHO-5 → 質問紙の39項目（性格10・アバター意識3・スイッチ5・理想の頻度4・いまの頻度4・推し疲れ4・効果4・お金と時間5） |
| 毎週（6週間） | 会話インタビュー12項目（いまの頻度4・推し疲れ4・効果4）。2週ごとに WHO-5 |
| 3週目から（群B・C） | 今週の提案（最大2つの頻度を±1段階。「理想の頻度」を侵さない最大3案）。選ぶ／見送る（理由を任意で）。次のチェックインで実行できたか（できなかった理由も任意） |
| 群C | 「いまの状態」（レーダーチャート＋数値＋「この数字の根拠」）、「ミラー」（今のまま／提案どおりの似顔アバターと見込み） |

群は、記録のみの2週間のあと（15日目から）に割り付けた群の画面になります。それまでは全員、会話だけです。
`index.html?dev=1` で開くと、設定の下に「+1日」「+7日」「デモ回答を入れる」が出ます。

## 会話インタビューの仕組み（AI読み取り）

質問の文言は固定です（`js/instrument.js`）。AIインタビューの問いかけも、質問紙の項目の文をそのまま並べて作ります（`js/topics.js`、言い換えない）。自由な文を答えると、読み取り（AI または規則）が**項目ごとの1〜5**に直し、**必ず本人が画面で確かめてから**確定します。ボタンで答えた値はそのまま確定です。

| 読み取り | 使われ方 | 回答に残る印（`src`） |
|---|---|---|
| ボタン | 本人が直接選ぶ | `tap` |
| 規則（`js/extract.js`） | 1項目への短い返事（「やや当てはまる」「月12万」など）。あいまいなら読まずにボタンへ誘導 | `rules` |
| AI（`js/reader.js` → `server/proxy.js`） | 話題（例：推し疲れの4項目）への自由な1文をまとめて読み、足りない項目だけ1つずつ聞く | `llm` |
| 本人が直した | 確認カードで値を変えた | `rules+edit` / `llm+edit` |

`src` は書き出しに入ります。ボタン／文章／AI で回答の分布が変わらないか（測定の同等性）を、研究側で確かめられます。

AI読み取りは、同意画面で選んだ人だけ、サーバーが使えるときだけ有効です。APIキーはサーバーの環境変数にだけあり、ブラウザには置きません。サーバーは電話番号・メール・URLなどを伏せてから外部のAIに送り、本文を保存・記録しません。

## 最適度と微修正（`js/proposals.js`）

「いちばん幸せ」と答えた理想の頻度と、いまの頻度の近さを**最適度**として出します（4活動のずれ0〜4段階の合計を、最大16に対する割合で見る。質問紙の回答だけで、モデルの予測は使いません）。

- 最適度が **80%以上**：「すでにほぼ最適です」と表示し、提案は**微修正（1つだけ・1段階）**にします。理想に近づく案を先に、次に推し疲れが下がる見込みの案を出します。見込みが出なければ「今週はこのままで大丈夫」。
- 80%未満：理想に近づく組み替え案（最大2つの変更・最大3案）。
- 「この数字の根拠」で、活動ごとの理想・いま・ずれ、式、しきい値が見えます。しきい値80は仮の値です。「最適」は本人が答えた理想に近いという意味で、推し疲れの軽さや健康にとっての最適さは含みません。

## 「いまの状態」の数字の出し方（`js/state.js`）

質問紙と同じ項目の回答を、そのまま 0〜100 にします（(回答 − 1) ÷ 4 × 100）。推し疲れは大きいほど負担が重く、効果は大きいほど「当てはまる」です。

| 数字 | 計算式 |
|---|---|
| 軸（睡眠・金銭の不安・義務感・嫉妬と落胆／生きがい・自信・スケジュール・創作スキル） | 1項目の回答（1〜5）→ 0〜100。予備調査215名の中での位置（同じか低い人の割合）つき |
| 推し疲れ・効果の指標 | 各4項目の平均 → 0〜100。区分は215名の三分位 |
| 推し活費用の負担 | 推し活費用 ÷（手取り − 必要経費）。回答の範囲の中央値で換算した概算 |
| WHO-5 | 素点（0〜25）× 4 |

## 予測と提案（`js/model.js`、`js/proposals.js`）

入力は、いまの頻度4つ・アバター意識・スイッチ5項目。リッジ回帰（`analysis/model_v1.py`）で幸福度・推し疲れの指標を予測し、チェックインごとの本人とのずれで個人差を更新します（個人内の揺れ SIGMA_W = 0.4 は**仮の値**）。提案の差は、係数のばらつきから出した「ずれの大きさ（±）」つきで表示します。

## 動作確認

```bash
node --test tests/unit.test.js                                             # 単体テスト（24件）
node --test tests/photo.test.js                                            # 写真アバターの計算部分（27件）
(cd server && npm install && node --test)                                  # サーバー（偽のAIクライアントで34件）
PLAYWRIGHT_MODULE=<playwright の場所> node tests/e2e.js <出力先>             # ブラウザ（Chromium）での通し確認とスクリーンショット
PLAYWRIGHT_MODULE=<...> node tests/e2e_http.js <顔写真.png> <出力先>         # http での写真アバター → AI読み取りの入口（偽のAI）
PLAYWRIGHT_MODULE=<...> node tests/photo_e2e.js <顔写真.png> <出力先>        # 写真アバター単体（通信・保存・エラー）
```
顔写真はリポジトリに置いていません（試験には scikit-image の宇宙飛行士の画像を使いました）。

## 写真から作るアバター（`js/photo.js`、詳細は `PHOTO_AVATAR.md`）

顔の特徴点（MediaPipe Face Mesh、npm から取り込み、通信なしで動く）から、肌の色・髪の色・顔の比率（顔幅・あご・目の間隔・目の高さ）を出して似顔アバターに反映します。写真は端末内で処理して破棄し、保存も送信もしません（通信・保存・後始末は `tests/photo_e2e.js` で確認）。結果は必ずパーツ選択で直せます。髪型は特徴点から分からないので、本人が選びます。`http(s)` で配信したときだけ使えます（`file://` では写真ボタンを出しません）。

## まだ確かめていないもの・仮のもの

- **写真アバター**：試したのは1枚の実写（宇宙飛行士の画像）と合成画像だけです。実機のカメラ、スマホ（iOS Safari）、肌の色や人種ごとの精度、実際のメガネは未検証です。照明で肌の色が変わります（暗い写真は濃い肌色に見える）。顔の比率の基準値は仮です。

- **AI読み取りは、実際のAPIでは一度も動かしていません**（この環境にキーがありません）。偽のクライアントでの試験のみです。最初の実機確認の手順は `server/README.md`。
- 質問紙の選択肢の文言（「とても当てはまる」など）は、フォームの原文が手元になく仮です（`js/instrument.js` の `labelsConfirmed`）。
- 予備調査の回答は「1＝よく当てはまる」の逆向きだったので 6−x にそろえてあります。TIPI-J も同じ向きと仮定しています（フォームの文言で要確認）。
- 予備調査の対象はほぼ全員が大学生で、予測の当たり具合は低いです。提案の「見込み」は小さく、不確かです。
- 個人内の週ごとの揺れ（SIGMA_W）は仮の値です。
